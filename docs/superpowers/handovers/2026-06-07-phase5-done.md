## 4. Known limitations / deferred (carry forward)

1. **Provider switching is plumbed but not live in running agents.** `getProvider` is NOT wired into `src/run/agent-*.js` entrypoints — they still pass the static injected `provider`. Storage + API + UI + factory support exist; wiring the entrypoints to build `getProvider` from `repo.getAgentConfig` is a small follow-up.
2. **gemini/openai are UI options but not implemented.** `createProvider` only has `case 'local'`; selecting gemini/openai will throw at cycle time once #1 is wired (agent catches → abstain). Implement those providers (one switch branch each) before exposing them as working choices, or grey them out in the UI.
3. **No prod cron.** `docker-compose.prod.yml` has neither a `reliability` nor a `summary` service, so the digest (and the Phase 4 reliability loop) do NOT auto-run in the prod deploy. Add both services to the prod compose to actually ship the digest/reliability cron.
4. **Summary heartbeat fires on empty windows** (intentional). Early-return on `signals.length === 0` in `runSummaryOnce` to stay quiet.
5. **Disabling all voting agents would starve the emitter** (it waits for `expectedAgents` votes). UI doesn't guard against it.
6. **`ROSTER` duplicated** in `src/api/routes/agents.js` as the API's static source of truth (ids+weights mirror `src/agents/*/config.js`). If these ever move to a shared module, point the route + future `getProvider` wiring at it.
7. **Manual browser pass DEFERRED** (no infra in dev): Agents tab provider change → `PATCH /api/agents/:id` 200 → row persists on reload. Pages unit-tested (RTL/jsdom) + `vite build` clean.
8. Live `npm run db:migrate` on the VM to create `legion.agent_config` (idempotent, additive). Remember the deploy-order lesson: `compose build` before `run --rm … db:migrate` (PR #8).
